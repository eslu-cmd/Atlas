4. Atomic dictionary allocation

  
Allocates a (namespace, scope, token) atomically in Supabase. Re-submitting the same slot returns a conflict with the existing meaning. Shared-write enforcement starts here.

  
  
  
  
  
  
  
  


  
  






  
5. Transactional write proof

  
Three modes: write (insert+commit), rollback (insert+rollback — row must not persist), retry (same idempotency key twice — second returns the original). GET verifies durability.

  
  
  
  

  

    
    
    
    
  

  






  
6. Unauthorized-write rejection

  
The browser attempts to insert directly into Supabase using the public anon key. RLS must reject the write (401/403). Only the trusted service (service role, server-side) can write.
